# 実装設計の補足事項

## 開発方針とシステム構成
2026年10月15日にモックアップおよび実装方針の承認を受け、シラバス収集スクレイパーと閲覧用Webサイトの並行開発を進めている。認証機能は設けない構成とした。初期の調査基準として基本計画書（`docs/plans/syllabus-plan.html`）を維持しつつ、本補足事項により初期提案のスキーマを改訂する。実装上の型定義や契約は `src/lib/contracts.ts`、データベースの移行定義は `migrations/0001_initial.sql` および `0002_search.sql` を正とする。
全体の技術構成として、スクレイパーにはローカル環境で動作する Python と Poppler を採用した。Webサイト側は React、shadcn、Hono 公式の `@hono/inertia` 連携、Vite、Cloudflare Workers、Cloudflare D1 で構築する。現時点でリモートリソースは一切作成しておらず、ローカル環境での開発を完了させた後にデプロイを切り離して実施する。バックエンド API は `GET /`、`GET /courses/:id`、`GET /healthz` のみを提供し、更新処理を持たない読み取り専用として設計している。

## 科目の同一性判定と競合管理
教員や時間割が異なる別登録コードの授業は同名であっても別レコードとして分離し、同一PDFに複数コマが記載されている場合は1件の授業として管理する。科目の同一性は、開講年度（`year`）、学部（`department`）、時間割コード（`registration_code`）、バリアントキー（`variant_key`）の組み合わせで一意に判定する。同一URLのPDFが複数箇所に掲載されている場合は取得を重複排除しつつコマ情報を保持し、同一自然キーに別URLのPDFが割り当てられた場合は内容が一致していても自動統合せず競合として隔離する。元文書の URL ハッシュ値は不変として扱い、更新処理に失敗した場合でも以前の正常なデータを保持してデータの欠落を防ぐ。

## データベーススキーマと検索インデックス
データベースは `courses` テーブルを中心とし、`rowid` を整数主キーとして採用し、一意制約を持つ文字列型の `id` を保持する。関連テーブルとして `source_documents`、`imports`、`course_slots`、`course_pages`、`course_modalities`、および trigram を用いた FTS5 仮想テーブル `course_search` を定義した。初期計画にあった個別の `search_rowid` は廃止し、`courses.rowid` を共通利用することで全文検索インデックスとの結合処理を簡素化している。
`course_pages` には抽出した生のページテキストのみを保存し、全文検索用の `body_search` は正規化して集約した値を用いることで、冗長なページ単位の検索インデックス作成を排除した。また、解析時の警告情報（`parseWarnings`）、見出し欄から抽出された原表記のメタデータ（`raw_metadata`）、および判定根拠の情報（`evidence`）を欠落させずに保持する。

## 表記揺れの正規化とエイリアス管理
教員名と教室名は、画面表示用には原文の文字列を保持し、検索用には NFKC 正規化、小文字化、空白の除去を行い、各種 Unicode ハイフンを ASCII のハイフンに置換する。その他の検索項目は NFKC 正規化と小文字化に加え、連続する空白を単一の空白へ縮約する。
辞書設定 `config/aliases.json` は教員名と教室名に対応し、正規化された別名から標準の表示名への対応付けを行う。検索時には標準の検索用値を追加し、完全一致する検索語をエイリアス展開して処理する。同一人物の曖昧な名寄せ、イニシャルによる統合、建物名の推測による統合は行わず、初期状態の辞書は空とする。教員名は空白による分割を行わず、補助教員を含めて記録し、「他」の表記も推測で名前を補完せずにそのまま残す。教室名も学部情報や前後の空白から推測して補完しない。

## 開講コマ・授業形態判定・検索仕様
開講曜日は1（月曜）から7（日曜）の数値、時限は整数で管理する。曜日、時限、学期の検索では EXISTS 句を用いて同一スロット内の組み合わせであることを検証し、例えば月曜1限と火曜2限を持つ科目が「月曜2限」の検索に誤って一致することを防ぐ。集中講義や開講日時が不確定な場合は原文の表記を残し、数値項目は null とする。出所情報として HTML と PDF の両方の所在を記録する。
授業形態は、対面（`in_person`）、オンデマンド（`on_demand`）、同時双方向（`live_online`）、遠隔・詳細未定（`remote_unspecified`）、不明（`unknown`）の5種に分類する。単一の列挙型ではなく関連テーブル `course_modalities` を用いることで、複数の形態が混在する科目を明確に記録できる。判定はシラバス本文の明確な根拠のみに基づき、事前学習動画を伴う対面講義（`fs-FSE15500`）や明示的なオンデマンド（`com-BS107500`）のように実証できる形態のみを保持する。条件付きでオンラインと対面を併用する記述（`hs-HS900100`）や否定表現などの曖昧なケースは「不明」とし、警告を記録する。根拠があれば複数の形態を同時に保持できる。なお、「不明」は対面を意味しない。授業方法欄の「講義」や「演習」は授業形態を示すものではなく、「遠隔授業科目」欄が空欄であっても対面の証明にはならない。UI 上の「教授」という項目名は、非常勤講師等を含むため「教員名」と表記できる。
検索条件は、キーワード（`q`）、講義名（`title`）、教員名（`teacher`）、教室（`room`）、開講年度（`year`）、学部（`department`）、学期（`term`）、曜日（`day`）、時限（`period`）、授業形態（`modality`）を個別のフィルターとして分離した。キーワード検索は最大100文字、トークンは最大5個で各40文字以内とする。3文字以上のトークンは FTS5 の二重引用符付きリテラル検索、3文字未満は `instr` 関数による部分一致を行い、個別項目フィルターとは AND 条件で結合する。検索結果は20件に次ページ判定用の1件を加えた計21件を取得し、`title_search` および `id` で安定したソート順を保証する。ページ番号は1から1000まで対応する。動的な API 応答は初期状態で `no-store` とし、静的アセットのみハッシュ付きファイル名でキャッシュする。
