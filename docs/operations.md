## ローカル環境の初期構築
依存関係のインストール、ローカル D1 データベースへのマイグレーション適用、および開発サーバーの起動は以下の手順で行う。

```bash
pnpm install
python3 -m pip install -r scripts/ingest/requirements.txt
pnpm exec wrangler d1 migrations apply syllabus-db --local
pnpm dev
```

## シラバスデータの収集・抽出・反映手順
対象となる公開シラバスには21学部にわたり7,677件のリンクと6,461件の一意な URL が存在するが、すべての PDF で抽出品質が検証されているわけではない。事前のテキストサンプル精査（21学部24件。以前の統計は21件の PDF）では、「登録コード」や「時間割コード」、「授業科目」「授業題目」「授業科目名」「科目名」といった見出しの表記揺れや複数行の折り返し、複数教員や複数教室（`m-MH130300` や `bs-BSB04500` の4教室）、集中不定期（`com-BS107500`）といった多様な例外が確認されている。
データ収集にあたっては、まずシラバス URL の探索を実行する。

```bash
python3 scripts/ingest/main.py discover --output data --delay 1
```

次に、件数を制限したパイロット実行を行う。デフォルトの待機時間は1秒であり、全6,461件の初回収集には通信遅延や再試行を含めて約1.8時間以上かかる試算となるため、ダウンロード件数を絞ったパイロット検証として `--limit 30` を指定して実行する。

```bash
python3 scripts/ingest/main.py run --output data --delay 1 --limit 30
```

手元に既存の PDF サンプルがある場合は、他環境での `/tmp` の存在を前提とせず、`--offline-samples /path/to/samples` を指定してオフライン検証を実行できる。その際、ファイル名は `dept-CODE.pdf` の形式とする。
データの変換と抽出結果の検証は、SQL エクスポートと厳格なマニフェスト検証スクリプトを用いて行う。

```bash
python3 scripts/ingest/main.py export --output data --apply-sqlite
python3 scripts/ingest/validate.py --manifest data/manifest.json --samples data/samples --strict
```

これにより `data/import.sql` と `data/syllabus.sqlite` が生成される。厳格な検証を通過した後、ローカルの D1 データベースへデータを投入する。

```bash
pnpm exec wrangler d1 execute syllabus-db --local --file data/import.sql
```

## データ管理と運用上の留意事項
`data/` ディレクトリは `.gitignore` に指定されており、Git の管理対象外としている。取得した生の PDF や JSON ファイルには公開元の原データが含まれるため、リポジトリへの一括コミットや認証情報・秘密情報の混入を厳禁とする。
`run` サブコマンドは `--refresh` による再取得や、既存キャッシュを利用した中断箇所の再開に対応している。更新処理に失敗した場合でも過去の正常なデータは維持される。件数制限を外した全件実行は、パイロット実行の検証を完了した後にのみ行う。
教員名や教室名の表記揺れは機械的な自動名寄せを行わず、抽出結果を手動で確認した上で `config/aliases.json` を編集し、抽出およびエクスポート処理を再実行して反映する。安易な自動化による誤った保証を避ける運用を徹底する。
